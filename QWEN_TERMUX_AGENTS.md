# Qwen 2.5 в Termux — локальная система агентов

Эта часть проекта предназначена для Android + Termux без API и без обязательного облака.

## Цель

Запустить локальную GGUF-модель Qwen2.5-Coder через llama.cpp и использовать небольшой Python-оркестратор для цикла:

```text
Задача → Planner → Coder → Tester → Fixer → итог
```

Все агенты работают с локальными файлами проекта и системными командами Termux через Python `subprocess`.

## Что устанавливается

```bash
pkg update -y
pkg upgrade -y
pkg install -y git python clang cmake make
```

Для llama.cpp можно использовать пакет Termux, если он доступен в установленном репозитории. Если пакета нет, собрать llama.cpp из исходников.

## Модель

Для телефона с 8 ГБ RAM начать с:

```text
Qwen2.5-Coder-1.5B-Instruct Q4_K_M
```

или:

```text
Qwen2.5-Coder-3B-Instruct Q4_K_M
```

Для 12–16 ГБ RAM можно попробовать 7B в подходящей Q4-квантизации.

Модель должна быть локальным `.gguf` файлом, например:

```text
~/models/qwen2.5-coder-3b-instruct-q4_k_m.gguf
```

## Важное ограничение

Эта система не требует API-ключа. Но скачивание модели и исходных зависимостей требует интернета один раз. После загрузки модель и код могут работать полностью локально.

## Безопасное управление Termux

Агент не должен получать произвольный shell-доступ без ограничений. Рекомендуемый режим:

1. разрешить чтение/запись только внутри рабочего каталога игры;
2. разрешить команды сборки и тестов из белого списка;
3. запрещать `rm -rf`, запись за пределы рабочего каталога и изменение пользовательских конфигураций;
4. сохранять журнал выполненных команд.

## Предлагаемая структура

```text
agent_system/
├── README.md
├── config.py
├── llm.py
├── tools.py
├── agents.py
└── run_agent.py
```

Игра остаётся отдельным проектом. Система агентов не должна перемещать или удалять существующие исходники игры.

## Команды запуска

После добавления реализации:

```bash
cd agent_system
python run_agent.py "Добавь экран меню в игру"
```

Агент должен создать план, внести минимальные изменения, запустить тесты и вывести отчёт.

## Рекомендуемый игровой цикл

```text
1. Пользователь формулирует задачу.
2. Planner анализирует существующий код.
3. Coder изменяет только нужные файлы.
4. Tester запускает разрешённые тесты.
5. При ошибке Fixer получает stderr и исправляет код.
6. Цикл повторяется до успешного теста или ограничения количества попыток.
7. Изменения и результаты сохраняются в журнале.
```
