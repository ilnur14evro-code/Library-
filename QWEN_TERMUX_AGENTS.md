# Qwen 2.5 в Termux — локальная система агентов

Эта часть проекта предназначена для Android + Termux без API и без обязательного облака.

## Цель

Запустить локальную GGUF-модель Qwen2.5-Coder через `llama.cpp` и использовать Python-оркестратор для цикла:

```text
Задача → Planner → Coder → Tester → Fixer → итог
```

Все агенты работают с локальными файлами проекта и системными командами Termux через Python `subprocess`.

## Установка

### 1. Обновить Termux

Рекомендуется актуальная сборка Termux из F-Droid или GitHub Releases.

```bash
pkg update -y
pkg upgrade -y
```

Если появляется сообщение о невыбранном зеркале или проблеме репозитория:

```bash
termux-change-repo
```

Выберите основной репозиторий Termux и повторите:

```bash
pkg update -y
```

### 2. Установить зависимости

```bash
pkg install -y git python clang cmake make
pkg install -y llama-cpp
```

Проверка:

```bash
command -v llama-cli
llama-cli --version
```

Пакет `llama-cpp` присутствует в Termux main; для первого запуска дополнительный GPU backend не требуется.

Если пакет не находится:

```bash
termux-change-repo
pkg update -y
pkg install -y llama-cpp
```

### 3. Скачать этот репозиторий

```bash
cd ~
git clone https://github.com/ilnur14evro-code/Library-.git
cd ~/Library-
```

При обновлении существующей копии:

```bash
cd ~/Library-
git pull
```

### 4. Подготовить модель

```bash
mkdir -p ~/models
```

Для 8 ГБ RAM начать с:

```text
Qwen2.5-Coder-1.5B-Instruct Q4_K_M
```

или:

```text
Qwen2.5-Coder-3B-Instruct Q4_K_M
```

Для 12–16 ГБ RAM можно попробовать 7B Q4.

Модель должна быть локальным `.gguf` файлом, например:

```text
~/models/qwen2.5-coder-3b-instruct-q4_k_m.gguf
```

Измените `MODEL_PATH` в `agent_system/config.py`, если имя отличается.

### 5. Проверить локальный inference

```bash
cd ~/Library-/agent_system
python -c "from llm import ask; print(ask('Ответь одним словом: готов'))"
```

До запуска агентов эта команда должна успешно вернуть ответ модели.

## Безопасное управление Termux

Агент не должен получать произвольный shell-доступ без ограничений.

1. Разрешено чтение/запись только внутри рабочего каталога игры.
2. Разрешены только команды из белого списка `ALLOWED_COMMANDS`.
3. Команды удаления файлов (`rm`, `git clean` и аналогичные) в агентный контур не добавляются.
4. Пути с `..` и абсолютные пути из ответа модели отклоняются.
5. Результаты команд сохраняются в журнале.

Система предназначена для сохранения существующих файлов и добавления/изменения кода только в рамках проекта.

```text
agent_system/
```

Игра остаётся отдельным проектом. Система агентов не должна перемещать или удалять существующие исходники игры.

## Запуск

После установки:

```bash
cd ~/Library-/agent_system
python run_agent.py "Добавь экран меню в игру"
```

Агент должен создать план, внести изменения, запустить тесты и показать отчёт.

## Рекомендуемый игровой цикл

```text
1. Пользователь формулирует задачу.
2. Planner анализирует существующий код.
3. Coder формирует изменения.
4. Изменения проверяются по пути и формату.
5. Tester запускает разрешённые тесты.
6. При ошибке Fixer получает stderr и исправляет код.
7. Цикл повторяется до успешного теста или ограничения количества попыток.
8. Изменения и результаты сохраняются в журнале.
```

## Важное ограничение текущей версии

API-ключ не нужен. Интернет нужен только для первоначальной установки пакетов, получения репозитория и загрузки GGUF-модели. После этого inference выполняется локально через `llama-cli`.

Текущая версия ограничивает shell-команды, но перед использованием на важной игре рекомендуется добавить резервные копии и patch/diff режим перед заменой существующих файлов.
